# 原始记录自动生成（顺德）

> 道路运输液体危险货物罐式车辆检验报告 → 原始记录，一键生成与三层自动校验工具
> 版本标签：**原始记录自动生成26国庆版**（2026-10）

把对方发来的检验报告（Word/WPS 文档或 zip 压缩包）放进文件夹，程序自动完成
**解压 → 格式转换 → 数据提取 → 模板填充 → 充装介质附页无损搬运 → 并行生成成品 → 异构校验 → 渲染像素闸门**
全流程，每份报告平均一两秒，交付前自动列出漏份、失败、异常介质等全部风险名单。

---

## 一、功能特性

### main.py —— 成品生成

- **全字段自动提取**：号牌、使用单位、罐体材质/厚度、20 个测厚点、适装介质列表、检验/审核/下次检验日期等 40+ 字段，按内容关键词定位表格，不依赖固定表序，兼容多种报告版式。
- **充装介质附页整页照搬**：源报告末尾的「充装介质附页」连同正文、表格、印章图片、页眉页脚、页面分节几何、样式定义一并无损搬到成品末尾；自动处理样式撞名、关系 ID 重映射，并按需求剔除成品附页页码。
- **压缩包全自动处理**：识别 `检验报告/` 下的 zip 并解压（兼容 Windows 压缩包的 GBK 文件名、最多 3 层嵌套 zip、Zip-Slip 路径防护），按压缩包内子文件夹自动分批；`.7z/.rar` 与坏包点名告警。
- **旧格式自动转换**：`.doc/.wps/.docm` 通过 WPS（COM）静默批量另存为 `.docx`，转换失败的源文件逐份点名，杜绝静默缺份。
- **8 进程并行生成** + 成品**临时文件原子替换**保存（异常中断不会损坏旧成品）。
- **附页页码二次核对**：含附页的成品首轮生成后，用 WPS 排版引擎求源附页节内页码并带页码重新生成。
- **命名互斥量单实例保护**，防止两个实例同时运行互删解压目录。
- 运行结束输出交付清单：**未生成成品的源报告、转换失败、坏压缩包、非汽油/柴油介质、桂字头号牌、超长地址、含/缺附页、失败文件**。

### check.py —— L2 异构校验（数据正确性）

- **双通道独立解析**：python-docx 通道 vs 直接读取 zip 内 `word/document.xml` 原始 XML 的独立实现，44 个字段 + 介质列表逐字段三方比对，共享解析器的盲区无法蒙混过关。
- **fail-closed**：报告编号/号牌等关键标识缺失即判失败，禁止「空数据 → 全空成品 → 假成功」。
- **每批次随机抽样 5%（至少 1 份）生成 HTML 人工复核单**（带侧边栏目录，手机/浏览器可看）。

### verify.py —— L3 渲染闸门（交付前终极校验）

- 调用 **WPS 排版引擎把源报告与成品导出为 PDF**，再用 **PyMuPDF 渲染成位图**：
  - **附页逐像素比对**：声称「整页照搬」就必须在同一排版引擎下渲染一致，标点压缩、印章丢失、样式撞名等亚像素差异全部现形；仅同步遮蔽双方页码区（页码按需求已从成品剔除）。
  - `--full-text` **全量文本层闸门**：全部成品的 44 字段 + 介质列表逐一核对是否真实出现在 PDF 文本层（第三独立通道，不经 python-docx）。
- 支持按批次过滤（`python verify.py 6-8月份结算`）、自定义 DPI 与容差。

### run_all.py —— 一键编排

`check → verify` 顺序执行，subprocess 隔离，实时透传输出；任一环节失败返回非零退出码。

### gui.py —— 桌面图形界面（可选）

- 基于 **PySide6（Qt）** 的 GUI 外壳，按钮一键运行 main / check / verify / run_all，实时显示终端输出，可直接打开输出目录与抽样复核 HTML。
- 只做界面与子进程调用，不改动四个业务脚本的任何逻辑；支持 PyInstaller 打包成单 exe（模板与 `_deps/` 随包内置）。
- 不使用 GUI 时无需安装 PySide6，命令行工作流完全独立可用。

## 三、运行环境

- **操作系统**：Windows（依赖 WPS COM 组件）
- **Python**：3.13（3.10+ 应可运行，未逐一验证）
- **WPS Office**：需本机安装，程序通过 `KWps.Application` 调用（用于 `.doc/.wps` 转换、附页页码计算、PDF 导出）
- **Python 第三方库**：

```bash
pip install python-docx lxml PyMuPDF

# 仅在使用桌面 GUI 时额外需要：
pip install PySide6
```

- **pywin32**：已随仓库内置在 `_deps/`（程序启动时自动注册到 `sys.path` 并加载 DLL），无需另行安装；如使用自己的虚拟环境也可 `pip install pywin32`。

## 四、快速开始

```text
项目根目录/
├── 检验报告/            ← 第 1 步：把报告 zip 或文档放进去
├── 原始记录模版2.0.docx
├── main.py
├── check.py
├── verify.py
├── run_all.py
└── gui.py（可选）
```

```bash
# 1. 生成成品（自动解压/转换/分批/并行）
python main.py

# 2. 交付前校验（二选一）
python run_all.py            # 先 check 异构校验，再 verify 渲染闸门
python check.py              # 只跑数据校验 + 抽样复核单
python verify.py             # 只跑附页像素闸门
python verify.py --full-text 6-8月份结算   # 全量文本层模式，仅校验指定批次

# 3. 可选：图形界面
python gui.py
```

常用参数（`run_all.py` 会把批次名透传给 verify）：

| 命令 | 作用 |
| --- | --- |
| `python run_all.py --skip-verify` | 只跑 check |
| `python run_all.py --skip-check` | 只跑 verify |
| `python run_all.py --full-text` | check + verify 全量文本层模式 |
| `python verify.py --dpi 150` | 指定渲染分辨率（默认 110） |
| `python verify.py --tol 50` | 允许差异像素字节数（默认 0，严格） |

**输入支持的三种形态**（自动识别，可混用）：

1. `检验报告/` 下放 zip 压缩包（自动解压，包内每个子文件夹 = 一个批次）；
2. `检验报告/` 下放手动解压好的子文件夹；
3. `检验报告/` 根目录直接散放报告文档（批次名取「检验报告」）。

成品输出到 `原始记录汇总/<批次名>原始记录/`，文件名在报告名基础上加「原始记录」后缀。
所有终端输出同时保存在 `终端结果/<脚本>运行日志/`，日志按报告编号范围命名（如 `B-WTQC20261001-1041.log`），同批次重跑直接覆盖。

## 五、质量保障设计

```text
检验报告 (docx/doc/wps/zip)
        │  ① main.py：解压 → 转换 → 双通道字段提取 → 模板填充 → 附页搬运 → 8进程并行
        ▼
原始记录成品 docx
        │  ② check.py：python-docx vs 原始XML 异构逐字段比对 + 5% 抽样人工复核单
        ▼
        │  ③ verify.py：同一 WPS 引擎导出 PDF → 附页逐像素比对 + 全量文本层核对
        ▼
   交付（终端输出全部风险名单：漏份/失败/异常介质/超长地址/缺附页……）
```

- **异构双通道**：生成与校验不共用同一套解析逻辑，避免同因错误自我证明。
- **fail-closed 原则**：任何关键环节失败都落成显式问题记录，绝不静默产出。
- **成品原子保存**、**单实例互斥**、**解压路径穿越防护**、**COM 弹窗抑制与坏文件隔离**。
- **退出码即结论**：全部通过 0，存在未处理问题非 0，可接入计划任务/批处理判定。
